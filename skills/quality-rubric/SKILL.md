# Quality Rubric — 内功：质量护城河

This document is the human-readable specification of the deterministic quality gate.
It mirrors `lib/quality.py` **exactly** — the two MUST be kept in sync. If you change a
dimension, a weight, the pass threshold, or the anti-slop ban list here, change it in
`lib/quality.py` (and `skills/seo-content/SKILL.md` for the ban list) in the same commit.

**内功：质量护城河 — 拦截 AI slop、保证 information gain 与内链闭环。**
A page is generated by the writer model, then scored here with NO further LLM call. The
score is a pure, deterministic function of the page plan, the model output, and the
industry config. Pages at or above the threshold are published / previewed as live;
pages below it are previewed but flagged and NOT published.

> This file is documentation, not an LLM prompt by default. It is loadable via
> `llm.load_skill("quality-rubric")` if a future LLM-judge dimension is added.

## Pinned contract (mirrors `lib/quality.py`)

```python
PASS_THRESHOLD: float = 70.0   # a page passes iff score >= 70.0

def score_page(page: dict, content: dict, industry: dict) -> dict:
    # returns EXACTLY:
    # {
    #   "score": float,        # 0..100, rounded to 1 decimal
    #   "breakdown": dict,     # {dimension: {"score": float, "max": float, "notes": str}}
    #   "issues": list[str],   # actionable; empty if perfect
    #   "passed": bool,        # score >= PASS_THRESHOLD
    # }
```

Helper functions (also pinned, reusable by `app.py` / tests):

```python
def strip_html(html: str) -> str          # visible text only
def word_count(html: str) -> int          # words in stripped text
def extract_links(html: str) -> list[dict]   # [{"href": str, "anchor": str}, ...]
def count_headings(html: str) -> dict     # {"h1": int, "h2": int, "h3": int}
```

`score_page` MUST NOT raise on malformed HTML: a dimension that fails to parse scores 0
and records an issue. `score = sum(breakdown[*].score)`, rounded to 1 decimal.

## The six dimensions (sum = 100 points)

| Dimension | Max | Rule (deterministic) |
|---|---|---|
| **keyword_usage** | 15 | `target_keyword` (case-insensitive, minor token reorder allowed) appears in: title (+5), meta_description (+3), an `<h2>/<h3>` OR the first 150 words of body (+4), and 1–4 times total in body without stuffing (+3; **>6 occurrences = −3** "stuffing"). |
| **structure** | 20 | Exactly one `<h1>` (+5; 0 or >1 → 0 + issue); ≥3 `<h2>` (+5); no skipped heading levels e.g. h2→h4 (+3); ≥1 `<ul>`/`<ol>`/`<table>` (+4); ≥1 `<h2>` phrased as a question ending in "?" (+3). |
| **depth_wordcount** | 20 | `word_count(strip_html(html))`. Pillar: ≥1800 words → full 20, linearly scaled from 400. Non-pillar: ≥900 → full 20, linearly scaled from 400. **<400 words = hard issue, ≤5 pts.** |
| **internal_links** | 20 | Parse `<a href>`. Cluster page: links to `pillar_url` exactly once (+8) AND 2–3 sibling links from the cluster set (+8). Pillar: links to ALL siblings (+16, scaled by fraction linked). Penalize forbidden anchors ("click here"/"read more"/"this page"/empty/bare-URL): **−4 each, floor 0.** +4 if every anchor is descriptive (≥2 words, not a URL). Links to slugs outside the cluster set get no credit and raise an issue. |
| **specificity_antislop** | 15 | +8 if body has ≥3 "spec signals": a number followed by a unit/standard token (`mm`, `g/m²`/`gsm`, `Martindale`, `ISO \d`, `ASTM`, `N/25mm`, `MOQ`, `%`, certs REACH/RoHS/OEKO-TEX, Wyzenbeek, SAE J, GRS, Prop 65). **−3 per banned anti-slop phrase** (case-insensitive), floor 0. +7 if zero banned phrases AND ≥1 named cert/standard. |
| **meta_title_quality** | 10 | Title length 50–60 chars (+4; partial +2 for 40–65); meta length 140–160 (+4; partial +2 for 120–170); meta is not equal to the title and not a prefix of the title (+2). |

`PASS_THRESHOLD = 70.0`. A page passes iff `score >= 70.0`.

## Anti-slop ban list (mirrors `skills/seo-content/SKILL.md` verbatim)

Matched case-insensitively in the visible body; each occurrence costs −3 in
`specificity_antislop`:

- "in today's fast-paced world"
- "delve" / "delve into" / "dive into"
- "comprehensive"
- "it is worth noting"
- "it is important to understand"
- "in conclusion"
- "navigating the complex landscape"
- "unlock" / "elevate" / "leverage"
- "robust" / "seamless" / "cutting-edge"

## Spec signals (specificity)

A page "earns specificity" only with concrete, verifiable numbers and named standards —
AI-generated vague benchmarks do not count. Examples that match: `1.2 mm`, `350 g/m²`,
`Martindale 50,000`, `ISO 5470-2`, `ASTM D4157`, `25 N/25mm`, `MOQ 1,000 m`, `≥4`,
`REACH`, `RoHS`, `OEKO-TEX 100`, `Wyzenbeek 100k`, `SAE J2527`, `GRS`, `Prop 65`.

## Rationale (why these dimensions)

- **Information gain is the #1 2026 lever.** `specificity_antislop` + `depth_wordcount`
  push the writer toward real specs, certs and synthesis instead of generic filler.
- **Scannable structure** (`structure`) matches how buyers and AI answer engines parse a
  page: one H1, question-style H2s, lists/tables for specs.
- **Topic-cluster link closure** (`internal_links`) keeps the pillar→cluster→pillar graph
  intact; broken or "click here" links leak authority and signal low quality.
- **Keyword + meta/title hygiene** (`keyword_usage`, `meta_title_quality`) covers the
  basic on-page levers without over-optimizing into stuffing.

## Issues are actionable

`issues` are human-readable, copy-pasteable fixes, e.g.:

- `"Only 1 H2 found; need >=3 for scannable structure"`
- `"Banned AI-slop phrase: 'comprehensive'"`
- `"Missing internal link up to pillar"`
- `"Meta description 188 chars (target 140-160)"`
- `"Only 1 words; thin content (<400) will not rank"`

An empty `issues` list means a perfect page. The list is surfaced in the local preview
(`lib/preview.py`) and merged into the published-result warnings by `run.py`.
