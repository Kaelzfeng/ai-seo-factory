## 1. 任务一 · 把 Demo 部署到客户能访问

### 推荐路径（零风险、几分钟）：本机跑 + Cloudflare Tunnel 出一个公网 HTTPS 链接

为什么这样：不用买服务器、不用配 nginx，客户拿到一个 `https://xxx.trycloudflare.com` 链接就能打开；
本机一关隧道就断，安全可控。SSE 流式日志在隧道下正常工作。

```powershell
# 1) 一次性准备
git switch main                       # 用稳定分支
git pull
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env                # 见第 4 节填 key

# 2) 起服务（保持这个窗口开着）
python app.py                         # 监听 http://127.0.0.1:5000

# 3) 另开一个窗口，起隧道（装一次 cloudflared：winget install Cloudflare.cloudflared）
cloudflared tunnel --url http://127.0.0.1:5000
#   → 终端会打印一个 https://<随机>.trycloudflare.com，把它发给客户
```

### 验收标准（自己先点一遍）
- 客户打开链接 → 页面顶部绿色 **🎬 一键样板演示** 按钮 → 看到整组互链的 PU 合成革样板站、带质检看板。
- 这条路是 **零 key、零 WordPress、不调任何模型** 的（走 `/demo` 路由），**永不翻车**，是给客户的安全开场。

> 备选（要固定网址时）：把仓库部署到 Render / Railway 这类托管，用 `waitress` 起 WSGI。
> 这是增量、可后置；**首轮成交用上面的隧道方案足够**。需要我搭一键启动脚本就说一声。
